3.1 CREATE: deploy.sh (Main deployment script - runs on JUMP SERVER)
--------------------------------------------------------------------

Key features:
- Reads DEPLOY_TARGET from environment (set by convenience scripts)
- Validates all required configuration variables
- NO hardcoded defaults (security requirement)
- Builds Docker images, exports them, transfers to target server
- Cleans up local environment after deployment

Template structure:
#!/bin/bash
set -e  # Exit on any error

# Load .env file
set -o allexport
. .env
set +o allexport

# Validate DEPLOY_TARGET (stage or production)
DEPLOY_TARGET="${DEPLOY_TARGET:-stage}"
DEPLOY_TARGET=$(echo "$DEPLOY_TARGET" | tr '[:upper:]' '[:lower:]')

# Set server configuration based on target
if [ "$DEPLOY_TARGET" == "production" ]; then
    SERVER_USER="${PRODUCTION_SERVER_USER}"
    SERVER_IP="${PRODUCTION_SERVER_IP}"
    SSH_KEY="${PRODUCTION_SERVER_SSH_KEY}"
    REMOTE_BASE_DIR="${PRODUCTION_SERVER_BASE_DIR}"
    SERVER_NAME="PRODUCTION"
elif [ "$DEPLOY_TARGET" == "stage" ]; then
    SERVER_USER="${STAGE_SERVER_USER}"
    SERVER_IP="${STAGE_SERVER_IP}"
    SSH_KEY="${STAGE_SERVER_SSH_KEY}"
    REMOTE_BASE_DIR="${STAGE_SERVER_BASE_DIR}"
    SERVER_NAME="STAGE"
else
    echo "ERROR: Invalid DEPLOY_TARGET"
    exit 1
fi

# Validate required variables (NO DEFAULTS)
if [ -z "$SERVER_USER" ] || [ -z "$SERVER_IP" ] || [ -z "$SSH_KEY" ] || [ -z "$REMOTE_BASE_DIR" ]; then
    echo "ERROR: Missing required ${SERVER_NAME} server configuration!"
    exit 1
fi

# Rest of deployment logic...
# 1. Clean up local Docker
# 2. Reset git and pull latest code
# 3. Build and export Docker images
# 4. Copy files to export directory
# 5. Transfer to target server
# 6. Clean up local environment

See the actual deploy.sh file in this repository for complete implementation.

3.4 CREATE: deploy-on-server.sh (Runs on TARGET SERVER - stage or production)
--------------------------------------------------------------------

CRITICAL: This script must use TARGETED cleanup, not remove all Docker resources!

WRONG WAY (removes ALL Docker containers/images on server):
docker stop $(docker ps -aq)
docker rm $(docker ps -aq)
docker rmi -f $(docker images -aq)

CORRECT WAY (only removes project-specific resources):

#!/bin/bash

# Deploy on Server Script
# This script runs on the TARGET SERVER (stage or production)
# It loads Docker images and starts containers

set -e

echo "=========================================="
echo "Starting Deployment on Server"
echo "=========================================="

# Load environment variables
set -o allexport
. .env
set +o allexport

# Stop and remove ONLY project-specific containers
echo "Step 1: Stopping existing project containers..."
docker stop PROJECT-APP-CONTAINER PROJECT-MONGODB-CONTAINER 2>/dev/null || echo "No project containers running"
docker rm PROJECT-APP-CONTAINER PROJECT-MONGODB-CONTAINER 2>/dev/null || echo "No project containers to remove"

# Remove ONLY project-specific images
echo "Step 2: Removing old project images..."
docker rmi PROJECT-APP-IMAGE:latest PROJECT-MONGO-IMAGE:7.0 2>/dev/null || echo "No old images to remove"

# Show ONLY project containers/images
echo "Project containers before deployment:"
docker ps -a | grep -E "CONTAINER ID|PROJECT-NAME" || echo "No project containers"

echo "Project images before deployment:"
docker images | grep -E "REPOSITORY|PROJECT-NAME" || echo "No project images"

# Load new images
echo "Step 3: Loading Docker images..."
docker load -i cixio-com-app.tar
docker load -i cixio-com-mongo.tar

# Start containers
echo "Step 4: Starting containers with docker-compose..."
docker-compose up -d

# Verify deployment
echo "Step 5: Verifying deployment..."
docker ps | grep -E "CONTAINER ID|PROJECT-NAME"

echo "=========================================="
echo "Deployment Completed Successfully!"
echo "=========================================="

**IMPORTANT: Replace these placeholders with your actual project names:**
- PROJECT-APP-CONTAINER → e.g., cixio-com-app
- PROJECT-MONGODB-CONTAINER → e.g., cixio-com-mongodb
- PROJECT-APP-IMAGE → e.g., cixio-com-app
- PROJECT-MONGO-IMAGE → e.g., cixio-com-mongo
- PROJECT-NAME → e.g., cixio-com

These names come from your docker-compose.yml file!

# Simple Deployment Guide

## Files You Need to Know

### On Jump Server (3 files):
1. **deploy-stage.sh** - Deploy to stage server
2. **deploy-production.sh** - Deploy to production server  
3. **deploy.sh** - Main deployment script (called by above)

### On Target Server (1 file):
1. **deploy-on-server.sh** - Runs on stage/production server to start containers

## Quick Usage

### Deploy to Stage:
```bash
./deploy-stage.sh
```

### Deploy to Production:
```bash
./deploy-production.sh
```

That's it! The scripts handle everything automatically.

## What Happens Behind the Scenes

### Jump Server (deploy.sh):
1. Builds Docker images
2. Exports images to files
3. Copies everything to target server
4. Cleans up local files

### Target Server (deploy-on-server.sh):
1. Stops old project containers (only)
2. Removes old project images (only)
3. Loads new images
4. Starts new containers

## Configuration

All settings are in .env file:
- STAGE_SERVER_IP - Stage server address
- PRODUCTION_SERVER_IP - Production server address
- STAGE_SERVER_USER - Stage SSH user
- PRODUCTION_SERVER_USER - Production SSH user
- STAGE_SERVER_SSH_KEY - Stage SSH key path
- PRODUCTION_SERVER_SSH_KEY - Production SSH key path

## That's All!

No need to maintain multiple files or remember complex commands.
Just run ./deploy-stage.sh or ./deploy-production.sh and you're done.

STEP 9: COMMON ISSUES AND SOLUTIONS
================================================================================

9.1 Issue: "export: not a valid identifier" error
    Cause: Special characters in .env values (< > & |)
    Solution: Add quotes around the value
    Example: EMAIL_FROM="Team <email@domain.com>"

9.2 Issue: All Docker containers stopped on server
    Cause: Using "docker stop $(docker ps -aq)"
    Solution: Use targeted cleanup with specific container names
    Example: docker stop project-app project-mongodb

9.3 Issue: Missing required configuration variables
    Cause: .env file not updated or variables not set
    Solution: Copy values from .env.example to .env and update

9.4 Issue: SSH connection fails
    Cause: Incorrect SSH key path or permissions
    Solution: 
    - Verify SSH key exists: ls -l ~/.ssh/id_ed25519
    - Check permissions: chmod 600 ~/.ssh/id_ed25519
    - Test connection: ssh -i ~/.ssh/id_ed25519 user@server

9.5 Issue: "Permission denied" when running scripts
    Cause: Scripts not executable
    Solution: chmod +x *.sh
